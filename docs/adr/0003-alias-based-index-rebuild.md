# 索引重建用别名切换，校验通过后再切换

## 背景与决定

C40 要求索引可重复全量重建、不做增量同步。重建期间不能让关键词搜索不可用。

决定：对外只暴露别名 `products`，物理索引按版本命名（`products_v1`、`products_v2`…）。重建流程固定为：建新索引 → bulk 导入并逐项检查 → refresh → 全量校验（商品集合与筛选排序字段）→ 原子切换别名 → 冒烟查询 → 删除旧索引。

## 理由

- 重建期间搜索不中断；校验失败时旧索引仍在服务，可直接回滚。
- 别名切换是原子操作，避免「旧索引已删、新索引未好」的空窗。
- 16 件商品可以全量比对，校验成本可忽略。

## 考虑过的其他方案

- **直接删旧索引再建**：实现最简，但重建窗口内关键词搜索失败或返回空，且失败后没有回退点。
- **双写 / 增量同步**：C40 已排除。

## 后果

- 多一层别名管理；旧索引要在切换并通过冒烟后清理，否则磁盘会累积（V14 观察占用）。
- bulk 返回 HTTP 200 不代表成功，必须检查 `errors` 与逐项结果；别名更新同样要检查返回。
- 测试与开发环境使用隔离的索引与别名，避免污染演示索引。

## 补充：并发重建与结果不确定的处理原则（2026-11-18 复审）

以下原则不改变前文的决定，只补实现落地后必须遵守的边界：

- **所有权**：`createIndex` 成功后才把目标索引记为「本次创建」。异常清理只允许删除自己创建的索引；别人的索引一律不碰。
- **版本冲突**：物理索引名取 `max+1` 不是原子操作。适配器把 ES 400 `resource_already_exists_exception` 识别为专门的「索引已存在」错误；重建据此重新读取现有索引、重新取号并重试（最多 5 次），冲突路径不删除任何索引。
- **建索引失败即中止**：`createIndex` 失败不得继续 bulk，避免 bulk 对不存在的索引自动建索引。
- **映射门禁**：bulk + refresh 之后、切换别名之前，回读目标索引的实际 mapping，校验 `name` / `brand` / `model`（`search_as_you_type` + `smartcn`）、`displayPriceCents`（`long`）、`productId` / `sales`（`integer`）、`slug` / `categorySlug`（`keyword`）；不符即失败且不切换别名。
- **切换结果不确定**：调用 `updateAlias` **之前**先记录「已发出切换尝试」。
  - 从未发出 → 别名不可能引用新索引，可安全清理；
  - 发出过但失败/结果不明 → 一律保留新索引，复查显示未引用也不能作为删除依据；
  - 发出并回滚成功 → 复查确认不含新索引后才可清理。

## 补充：同机互斥与「别名唯一目标」不变式（2026-11-18 第三轮复审）

第三轮复审在集成分支 `feat/phase4-search`（HEAD `b12f7a8`）的真实 ES 上复现：两次重建（含首次建索引）各自读到空集合或同一旧集合，互不知道对方，两次 `add` 都成功，别名 `products` 同时指向两个物理索引；HTTP `keyword=Apple` 因此返回重复条目。切换后的校验只断言 `targets.includes(indexName)`，没有断言目标唯一，所以两次都报成功。

- **同机串行（互斥锁）**：`src/search/rebuild-lock.ts` 提供基于文件的锁，默认 `<仓库根>/.run/es-rebuild.lock`（相对仓库根解析，不依赖启动时的 cwd）。锁记录 `pid`、进程启动时间与可执行路径，与 `scripts/es-stop.mjs` 的归属校验同一风格：
  - 持有者仍存活 → 立即失败，消息里给出持有者与锁文件位置；
  - 持有者已消失（或 PID 被复用且启动时间 / 可执行路径与记录不符）→ 视为过期，重命名隔离后清理并接管；
  - 锁文件损坏 → 立即失败并提示人工确认后删除。
  获取与释放在 `rebuildProductIndex` 内部完成，CLI 与直接调用都受保护；释放放在 `finally`，成功与异常两条路径都执行。锁路径可注入，默认套件使用临时路径，不触碰仓库 `.run`。
- **别名唯一目标不变式**：切换成功后查询 `aliasIndices(alias)`，必须 `length === 1` 且等于新索引。发现多个目标时先收敛：用一次 `_aliases` 请求移除除新索引外的全部目标，再复查；收敛请求失败或复查仍不唯一都按失败处理，保留现场——不回滚别名、不删除任何索引，并在消息里报告实际目标。
- **逐项失败原因**：适配器在 `errors` 为真时把 `action_results` 中失败项的动作与序号写进错误消息，便于定位是哪一条 `add` / `remove` 失败。

本轮回归：默认套件新增锁、唯一目标、并发与适配器用例；`pnpm test:es` 新增真实 ES 并发用例（第二次重建因锁立即失败、HTTP 列表 slug 无重复）。
